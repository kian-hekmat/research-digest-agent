# Phase 2: v2.2 Switch-over Implementation Plan

**Goal:** Move the live service from v2.1 to v2.2: Monday-only sends and prep, every subscription weekly, and a $50 monthly budget.

**Architecture:** `app/cadence.py` stays the single source of the send slots. Dropping Thursday from `SEND_WEEKDAYS` moves the send cron, the slot math and the due check together, and the prep cron is now built from the same constants. A data migration makes every subscription `weekly` and makes `weekly` the default. The budget is a settings default (`.env` doesn't override it; checked 2026-11-16).

**Tech Stack:** Python, FastAPI, SQLAlchemy and Alembic on Postgres, Temporal schedules.

**Spec:** `docs/public-launch-plan.md` v2.2: §0.2 (budget, cadence) and Phase 2's "v2.2 switch-over" item. Read the 2c plan's "Carried forward" section too (the first-cycle results, 2026-11-16).

## Global Constraints

- Send: **Monday 08:00 `America/New_York`**. Prep: **Monday 01:00 `America/New_York`**. Ingest is unchanged (21:30 daily).
- Budget: `openai_monthly_budget_usd` = **50.0**. The 80% and 100% behaviour is unchanged.
- Every existing subscription becomes `weekly`, and `weekly` is the default for new ones.
- Schedule IDs are unchanged (`send-prep`, `weekly-digest-emails`), so the live schedules update in place.
- No workflow changes shape, so in-flight workflow histories aren't affected. Deploy anyway with nothing running.
- Git: commit straight to `main`, lowercase past-tense messages, as the owner, with no AI attribution.
- The live worker mounts this checkout. Pause the three schedules and stop the worker **before the first code edit** (Task 0).
- **Tests whose expectations change with the spec** are listed by name in each task. Only those may change, and only to the new spec's values. Any other test that fails is reported to the owner before anything is changed.

## Review Focus

1. **A twice_weekly subscription created through the admin API after the switch** should be emailed weekly, never on a Thursday. `twice_weekly` stays in the enum (Postgres enum values can't be dropped cleanly) and means "every send slot", which is now Monday only. This is pinned in Task 1's due-check rows.
2. **The live schedules carry the Mon/Thu cron and a note.** On startup they must update in place to Monday only, not stay at Mon/Thu or gain a second schedule. Task 1 changes the update-in-place test to start from `"0 8 * * 1,4"`.
3. **A prep that catches up late on Monday** (the host was asleep at 01:00) must still serve that Monday's slot. It does as long as it runs before 15:00 ET (`PREP_LEAD` = 7 h). After that, the send's own prep path takes over. This is pinned in Task 1's `prep_slot` test.
4. **The first Monday edition after the switch** must cover the whole week since the previous edition, including papers ingested on Wednesday and Thursday nights, which used to go to a Thursday edition. Task 1 adds a full-week window test.
5. **The migration's downgrade** restores the `twice_weekly` server default but leaves rows `weekly`. The old rows weren't recorded, so they can't be restored, and the migration says so. Task 2's round-trip test pins this.
